# Mapping specification: shared tables

> Generated from the schema catalogue. Synthetic platform documentation.

## Table person

Table person: One row per synthetic person. The shared key for every pack. Names and identity numbers are not kept.
The table person is generated by scripts/gen_hospital.py.
The primary key of the person table is person_id.

- Column person.person_id has type VARCHAR and is required (not null). Meaning: Shared ID, e.g. PER000001.
- Column person.birth_date has type DATE and is required (not null). Meaning: Date of birth.
- Column person.death_date has type DATE and may be null. Meaning: Date of death. NULL if alive.
- Column person.gender has type VARCHAR and is required (not null). Meaning: M or F.
- Column person.state has type VARCHAR and may be null. Meaning: US state.
- Column person.is_policyholder has type BOOLEAN and is required (not null). Meaning: true if the person holds insurance (ClaimSense).
- Column person.is_bank_customer has type BOOLEAN and is required (not null). Meaning: true if the person banks with CreditGuard.

## Gold view person_360

Gold view person_360: Gold view. One row per person with activity counts from every pack. Use it for questions that compare packs per person.
The gold view person_360 reads the silver tables person, encounter, admission, prescription, policy, claim, payout, account, loan.

## Gold view drug_utilisation

Gold view drug_utilisation: Gold view. One row per drug with prescriptions, patients and pharmacy claims. Used to reconcile pharmacy claims with prescriptions (scenario X3).
The gold view drug_utilisation reads the silver tables drug, prescription, claim.
